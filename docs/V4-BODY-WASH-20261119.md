# V4 主体动态墨色修复验收

## 2026-11-19 — V4 主体动态墨色修复与玩法提案 [CURRENT]

发布键 `v4-body-wash-r14`。仅修改主体显示，不改拖尾速度场、体型/碰撞/成长公式、NPC或晕染规则。

- 根因是r13实体保底层：d=max(d,约2–3的高浓度)压平真实密度，灰阶指数映射饱和，静态纸纹无法呈现动态。不是碰撞虚线覆盖。
- 主体覆盖与墨色分离：真实coreRadius继续控制尺寸；内部用受限密度、连续域扰动、实际速度/浓度场及缓慢毛细混合显示浓淡，湿边扰动约±1.4%，停止仍有轻微流动。灰阶设计范围约12–53，外围沿用r13光学与惯性。CPU降级增加轻量动态墨色。无新FBO。
- 实测同一GPU状态修复前主体灰阶标准差0.50，修复后7.21；1.08r外全部RGBA差值为0。12组四体型×直行/转弯/停止动态像素检查、10组PC/手机主体半径、48组移动路径、8组GPU/降级裁切、8组实际游戏检查通过；6个针对性Node脚本通过。最终黑色主体半径约逻辑95%–102.5%。真机和最终美术仍待用户验收。
- 玩法研究已完成但未实施：优先A吞噬反馈/短目标/阶段回报，再原型B单眼球扇形+晕染消弹。黑洞、弹幕、规则变更均待确认。核实起始17墨晕染5秒只耗约1.889墨，不满足12墨落墨门槛；本轮保持不变。5–7分钟仅目标，旧近似脚本不能证明真实局时长。
- 详见docs/V4-BODY-WASH-20261119.md、docs/V4-GAMEPLAY-PROPOSAL-20261119.md。

## 实际变更

src/ink/hero-solid-shader.js：分离覆盖与灰阶，保留真实圆心/半径。内部连续墨洗由双线性实际速度、浓度与域扰动共同控制；GPU相位只随模拟step推进，暂停不自走。边缘在逻辑半径附近微扰，不锁死成长。采用无sin哈希避免观察到的噪声格缝。
src/ink/hero-ink.js：传递模拟相位，不改变模拟速度/灌墨/寿命。
src/reveal/renderer.js：仅CPU降级主体动态墨洗，不改尾迹。
index.html、visual-effects/v4.html：同步发布键。
