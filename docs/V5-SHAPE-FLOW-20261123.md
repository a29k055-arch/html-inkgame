# 《墨》V5｜形体水墨、游入生态与操作体验

日期：2026-11-23。只改V5；V4标签v4-ink-reveal（10ef89b）、旧src及index.html不改。接续6970ec5，并合入既有R7素材动画/批渲染与6d32f95发布修复，未改素材原图、独立演示或冻结参考。

## 对照截图确认的根因

1. 旧速度基准110、大体型约82–86世界单位/秒，镜头拉远后屏幕位移更小。大体型每秒只移动不到一个自身半径，尾墨容易堆在身后，不能只延长流体寿命解决。
2. 原玩家形态按躯干横截面半径缩放，鱼/龙脊线可达逻辑半径的10–24倍；变身镜头再为巨模型拉远，造成主体/画面同时忽大忽小。
3. 虾虽然使用纸片动画，旧NPC缓存绘制仍整体旋转；泡泡又裁了纸片身体。速度线随机铺全屏，桌面顶部仍是约96px大面板。
4. 原形态墨源只在后半脊线，并沿用单圆局部约束；本轮需要真正按全身形体注墨。

## 用户指定修改及实际参数

### 速度、阶段生态与边缘入场

- 常速基础180，体型减速最多约8%，最低166；额外以120屏幕像素/秒为补偿目标，常速世界上限400，鱼/晕染加速另算。目标受400上限约束，并非任何极端视口都能保证120屏幕像素/秒。普通NPC基准比例同步下调，避免它们随玩家一起突然变快。
- 开局仍10只；第一阶段虾出生/成长上限4.5，后续出生段为3.5–6.5、4–7.5、5–8；鱼、龟的阶段出生段也递增，后期更容易抽到较大个体。旧个体不清除。唯一大鱼/大龟仍在第二阶段后出现，各最多一只。
- 所有初生、重生、解锁大个体与龙从有效画纸外沿路线游入。未入纸时不碰撞、吃墨点、被吞或侵蚀，不被边界约束瞬移进去；入纸后约.8秒保护，再继续游向内水域。
- 龙仍首次60秒、场上最多一条、被吞30秒后再入场。镜头外有生物不等于已进入画纸；它会走完实际入境路程。

### 墨量资格与转向

NPC墨量按其实际质量r²设定并同步成长：虾1.2r²、鱼2r²、龟.7r²、龙7r²。例：r3虾10.8墨、r6.5鱼84.5墨、r28龟548.8墨；大鱼上限1800墨、大龟5420.8墨、龙4732墨。

玩家当前真实墨量（含临时乌龟墨）高于目标，并覆盖约80%本体即可吞噬；取消互相矛盾的躯干粗细资格。NPC互吞保留额外资源优势与消化间隔，阶段晋级仍仅用永久墨。吞噬收益暂保留原质量转移/收益上限，不等于把目标显示墨量100%直接加给玩家。

鱼、龟、龙实际速度方向分别限制约2/.8/1.5弧度每秒，反向时保留前进，走弧线掉头。虾按纸片左右翻面与有限倾斜，腿始终朝下；龟保留慢划肢，龙按R7连续S形与尾部方向历史运动。

### 十套素材、变身尺寸与泡泡

接入现有鱼04/01/02/04特别版、虾07/04/05、龟02/08、龙04。NPC稳定分配，吃下后继承具体rigId。没有生成新的素材。

玩家形态按实际主躯干Alpha面积归一为πr²，继续随墨量增长，并对半径变化做约.35秒平滑。显示与碰撞采样使用同一平滑尺寸，泡泡增长时不会先把逻辑圈瞬间撑大。形态只变长宽比例，不再把逻辑半径直接当细长身体的横截半径。

变身不再改变摄像机倍率；镜头可以平滑偏向主躯干质心，偏移最多视口18%，给长身体两端空间，不为全身装入而突然缩小整幅图。窄屏极端长尾仍可能部分出视口。

虾泡泡使用透明体积渐变、前后玻璃边与反光，不裁虾的身体/须尾；实体仍按泡泡本体，越圈装饰不额外扩大碰撞。

### 本轮重点：按形体散墨

鱼/龙/龟沿真实全身截面双侧注入同一个原生流体场，覆盖头到尾，局部宽度随实际身体。移除旧单圆material吸附和contain裁剪；没有叠一个黑色圆盘或另画轨迹线。

| 形态 | 局部墨源 | 总灌墨预算 | 移动浓度衰减 |
|---|---:|---:|---:|
| 鱼 | 24 | 16 | .30 |
| 龙 | 26 | 22 | .28 |
| 龟 | 16 | 3 | .40 |
| 虾 | 0 | 0 | 无水墨 |

两次批量GPU通道完成密度与局部速度，仍12个FBO。按世界坐标的细灰阶、局部剪切/小卷流与前后帧扫掠保持高速连续；旧墨不会整体跟身体转向。停止后加速散去，受控GPU检查3秒后Alpha为0。程序在开局转场准备，退出释放。跨物种变身时清一次视觉墨场，永久显画不清；同形态续时不清。

经过多轮实际观图，排除了早期纯软阴影、过重龟墨与规律粗涡旋。当前依据主躯干截面近似轮廓，不是每根独立鳍/足/触须的逐像素注墨；不能把测试通过等同于用户美术签收。CPU降级保留可玩性和裁切，不能声称与GPU全形体墨完全等价。

### 悬浮物与UI

悬浮物上限1400→1850、补充84→120/秒；40%补充尝试倾向玩家周围，避开身体和叶茎，近区软上限220，.45秒淡入。单点4/7/11墨的固定奖励不改，也没有整体放大成长倍率。

桌面顶部改为约41px长条，手机约44px；按住Shift显示独立加速/蓄墨/就绪提示，释放与冷却时消失。速度线收敛为桌面最多8、手机4条，短、淡、仅沿画面边缘出现，中心画作留空；仍可在下一轮按反馈关闭。

第四阶段外留白改3%，限制任何一侧不超过5%；前三阶段仍在画内。变身镜头使用同一缩放规则，不再通过拉远暴露大量框外空白。

## 自主配套调整（区别于直接需求）

1. 扁平条里增加一个近处目标的墨量资格提示：可吞/需多少墨。没有恢复NPC姓名/ID，也不满屏发光；提示仅表示墨量足够，仍需80%覆盖，入场/保护期不显示误导提示。
2. 危险提示、AI判断同步使用真实墨量资格；薄身高墨者不会被粗细半径误判，危险细线跟随本体截面。
3. R7共享运行时加入V5发布版本映射，防止新入口仍命中旧运行时缓存。
4. NPC使用48帧、龙72帧与透明度稳定插值，并按R7实际频率播放；玩家实时更新。共享图集约59.12MiB，启动资源124项、25.28MB，读量与动画准备分别显示。
5. 形态中心采样、泡泡平滑尺寸和预热/释放配套，避免新美术带来碰撞不同步或首次变身卡顿。
6. 玩家死亡回到早期阶段时，已成长的存活NPC不被上限反向缩小；新生个体才按当前阶段低位重来。修正旧手机CSS隐藏所有small元素导致新提示不可见的问题。

7. 图形故障切换到降级模式时保留生物动画、接触采样与镜头，避免重新出现旧敌人或因缺失接触采样而停住。

## 下一轮实际可做的玩法企划（本轮未直接实施）

用户截图6:30时有墨区域89.3%，已接近90%完成条件；因此旧版并非必然整体时长严重偏离5–7分钟。更明确的痛点是后期移动体感、可吞辨识、变身连续性和捕食奖励的读感。本轮补给/速度改变之后，应重新测自然局，而不是继续统一加倍率。
