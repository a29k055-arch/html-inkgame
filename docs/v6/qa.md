# 《墨》V6 测试记录

## V5 原生视效接入复验

《浅汀》种子 4 使用真实摇杆指令抵住红圈黑洞约一秒，玩家墨量从 100 降至 80.367，黑洞从 202 增至 221.633。双方转移 19.633 墨。另测包括主动游开、相隔 0.2 单位、不同刷新率以及十套生物从拾取到变形的素材编号一致性。14 组物理回归、四段教学的 25 个练习和 144 局路线回放通过。

## 一、移动、吞食与放墨

| 场景 | 检查结果 |
|---|---|
| 墨球移动 | 鼠标拖动、方向键、放墨按钮、触点归属、滚轮、双指缩放、失焦和取消输入通过事件回归。正常移动保留质量。 |
| 质量变化 | 红刺球与玩家等量损耗，红黑洞吸收玩家质量，蓝圈敌人可安全整只吞食。敌人同类相消、异类由大吸小。质量相等和最后一次接触均单独验证。 |
| 荷叶与散墨 | 放墨支付真实质量，叶内进入储墨，叶外延时产生墨点。同一份墨只能结算一次。测试覆盖自然开花、采花、三花容量上限和满叶外溢。 |
| 鲤鱼、虾、龟、龙 | 实测鱼泡推进、零后坐力与零墨耗，虾对散墨与可食敌人的不同吸引速度，龟和龙的敌触保护，以及鱼形结束时的窄门脱离。道具入栏后需单独启用。 |
| 不同刷新率 | 相同输入分别以 30、60、120 Hz 驱动，得到一致物理结果。 |

## 二、教学、随机布局与节奏

四段教学均以普通摇杆、交互键、道具使用指令逐段跑通。测试覆盖移动和吞食、敌人之间的接触、四形逐项拾取使用、向后放墨与荷花回收。自动输入没有阅读等待，教学运行用时不作为玩家教学时长。

六幅画各测试种子 0 至 999，共 6,000 个开局。全部通过同种子复现、敌人数范围、敌人身份唯一、边界与初始接触检查。每个开局在 350 个地图单位内至少有两个可食目标，初始其余敌人的总质量加上玩家质量均超过最大敌人。实战还会发生消耗与争食，因此另行运行整局测试。

整局测试的局部路线只看短边 27% 范围，使用七成摇杆寻找可食目标、墨点与荷花，遇红圈绕行。全图路线从全图选择目标，使用满幅摇杆。两者均不使用道具或喷墨，以同一物理规则测量路线本身的影响。第三组原地静候。750 秒是测试停止采样的时刻，游戏本身没有倒计时。

| 八个固定种子，每画编号 1 至 8 | 局部路线通关 | 局部路线中位 | 全图路线中位 |
|---|---:|---:|---:|
| 浅汀 | 8/8 | 4:47 | 2:18 |
| 荷隙 | 8/8 | 5:53 | 1:53 |
| 双刺渡 | 8/8 | 5:36 | 2:43 |
| 分墨湾 | 8/8 | 3:52 | 2:06 |
| 夹岸 | 8/8 | 5:18 | 3:17 |
| 合塘 | 8/8 | 4:34 | 3:20 |

共 144 次整局测试。局部路线吞下第一只蓝圈敌人的中位时间为 1.65 秒，48/48 通关，通关中位 5:04，范围 2:57 至 7:16，21 次落在五至七分钟内。全图路线 48/48 通关，中位 2:31。原地等待 48 次均未自动通关。分墨湾两条路线都较快，值得在真人试玩时单独观察。

初轮发现浅汀种子 4 在后段容易只剩两个红圈，玩家只好等待荷花。降低末段取食门槛后，局部路线 6:42、全图路线 2:35 跑通同一种子。种子抽样和电脑路线用于复现节奏，不足以推算首次真人通关时长。

## 三、从目录到下一幅画

使用 Windows 上的 Edge 158.0.4370.33，分别以 1440 × 900 桌面和 390 × 844、像素比 2 的触屏模拟进入真实网页。两种尺寸均完成目录加载、中日英切换、进入《游与食》、实际移动吞食、自动进入第二课、暂停退回目录、选择《浅汀》及缩放。小地图和三格道具栏正常绘制。两次运行均无未捕获的脚本异常和资源请求错误。

另用测试页把《浅汀》开局缩减为一个可吞食敌人，真实物理判胜后观察完整揭画，点击“进入下一幅”进入《荷隙》。回到目录并刷新后，《荷隙》仍然开放，第三幅仍上锁。该布局仅由测试服务器提供。上表六关使用游戏原始生成器和完整敌群。

## 四、旧渲染版性能基线（8732382）

以下帧间隔来自前一版。更换为 V5 原生流体与骨骼后的实测见文首修订记录。

在两种浏览器视口核查目录与首关截图。手机质量条、地图、三格背包和放墨键各有独立空间，触屏画布输出 780 × 1688。取《浅汀》开局玩家停留、敌人自由游动时连续 60 个帧间隔，桌面和触屏模拟均测得中位 16.7 毫秒，第 95 百分位 16.8 毫秒。

物理压力场景以《合塘》布局运行 360 秒并在玩家附近添加散墨，按一秒为一批统计。Windows x64、Intel Core Ultra X9 378H、Node 24.22.3 上，每个 60 Hz 物理步在 330 个样本中的中位均值为 0.064 毫秒，第 95 百分位为 0.090 毫秒。这个数字只计物理。移动视口模拟在桌面硬件上运行，手机持续发热后的帧率仍需真机观察。

另测 34 个敌人同时可见、持续龙形态的全图渲染。Intel Arc B390 使用 D3D11 硬件加速，桌面和触屏模拟各采 120 帧，两组帧间隔中位均为 16.7 毫秒，第 95 百分位均为 16.8 毫秒，超过 25 毫秒的帧数均为 0/120。

## 复现

在仓库根目录用 Node 22 或更高版本执行。

```sh
node tests/v6-physics.mjs
node tests/v6-input.mjs
node tests/v6-tutorial-and-physics-budget.mjs
node tests/v6-seeds.mjs 1000
node tests/v6-route.mjs 8 750
node tests/v6-browser.mjs --site-root dist-pages
```

最后一条使用打包后的 Pages 目录，检查两个 V6 入口和独立 V5 入口。直接从源目录验收 V6 可使用 `node tests/v6-browser.mjs --site-root . --source`。可用 `CHROME_BIN` 指定 Chromium 可执行文件，用 `V6_QA_SCREENSHOTS` 指定四张实景截图的输出目录。
